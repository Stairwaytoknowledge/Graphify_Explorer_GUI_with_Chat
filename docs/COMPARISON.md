# Wrapper vs upstream: measured comparison

Wrapper around [graphify](https://github.com/safishamsi/graphify);
see [NOTICE](../NOTICE).

Generated by `benchmarks/compare.py`. Single run on a single
machine; rerun to refresh.

- Test repo:    `https://github.com/pallets/itsdangerous`
- Test question: `What does itsdangerous protect against?`

Graph build time is the *control*: same engine either way, so
the wrapper is neither faster nor slower at the engine work
itself. The wrapper's gains are elsewhere.

## Steps from zero to a natural-language answer

Upstream CLI path:

- 1. install Python or uv
- 2. python -m venv .venv
- 3. activate venv
- 4. pip install graphifyy
- 5. git clone <url>
- 6. cd <repo>
- 7. graphify update .
- 8. graphify query "..."
- 9. open graphify-out/graph.html in browser
- 10. (no built-in NL answer)

Wrapper path:

- 1. double-click installer
- 2. paste URL or path
- 3. click Build/Refresh
- 4. click a node, type a question, hit Send

**10 steps vs 4 steps.**

## What the wrapper adds that upstream doesn't have

- Cross-platform double-click installers (CI-verified on
  Windows, macOS, Linux).
- An inline graph viewer + click-to-explore details panel.
- A natural-language answer step (Chat tab) that runs
  *entirely on-prem* via Ollama, grounded in the graph BFS
  output. The bare upstream CLI returns raw nodes and edges;
  turning that into prose is left to the user.

## What upstream still does better

- The vis.js HTML viewer is still the best graph visualization
  for repos beyond a few hundred nodes - the wrapper's inline
  matplotlib view is capped at 300 nodes.
- `--mode deep` and multimodal extraction (docs, papers, video,
  images) live behind the Claude Code slash command and need
  Claude Code installed; the wrapper can't drive them.
